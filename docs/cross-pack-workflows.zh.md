# 跨开发者、跨扩展包工作流：开发设计与实施计划

[English](cross-pack-workflows.md) · [UI 开发文档](plugin-ui.zh.md) · [清单规范](pack-spec.zh.md)

**状态：规划，尚未实现。本文不发布新 SDK 或可导入清单，也不表示已完成跨包验收。** 当前 `steps[].action` 只引用本包动作，`actions` 不能为空；[接口响应工具链 Demo](../examples/tool-chain-demo/README.zh.md)证明的是同包工具复用。

## 目标与边界

开发者甲发布 JSON 提取器，乙发布 JSON 节点选择器，丙发布 TypeScript 生成器，三个工具互不依赖、可独立安装和使用。第三方开发者或用户另建一个工作流包，只声明「甲的公开入口 → 乙的公开入口 → 丙的公开入口」。工具作者无需认识其他工具，也无需为了每种组合修改工具或复制实现。宿主负责解析依赖、传递数据、显示真实工具页面和管理执行。

首版只做有序串联，允许脚本与交互 UI 混合。分支、循环、并行、嵌套工作流、远程服务调用及自动恢复执行不在首版范围。

## 身份与公开契约

以下名称是**设计草案**，不是当前 manifest/SDK 字段；实施前冻结精确格式与版本门槛。

| 要素 | 计划契约 |
| --- | --- |
| 稳定包 ID | 发布者命名空间下的不可变 ID，例如 `dev.alpha.json-extractor`；独立于 Git URL、本地路径、显示名和当前安装 key |
| 稳定工具 ID | 包内不可变入口 ID，例如 `extract`；调用目标为「包 ID + 工具 ID」，不能靠标题、关键词或本机 UUID 寻址 |
| 公开入口 | 工具包显式导出可组合入口，绑定本包 action、执行模式（脚本或交互 UI）、契约版本、输入与输出描述；内部动作默认不可被外包调用 |
| 输入输出 | 有界 JSON 值；为每个入口声明可校验的结构、必填字段、大小限制、错误含义与副作用，输入在调用前校验，输出在交接前校验 |
| 工作流包 | 有自己的稳定 ID、元数据、依赖和步骤；允许不含工具 `actions`，仅引用公开入口，不能复制脚本或读依赖包的私有文件 |
| 版本 | 区分包版本和入口契约版本；依赖声明支持的版本范围，宿主锁定本次运行的已安装精确版本与资源摘要 |

示例引用（**概念表示，不是 JSON 清单**）：

```text
user.response-types
  dev.alpha.json-extractor / extract @ contract 1
  dev.beta.json-selector   / select  @ contract 1
  dev.gamma.ts-generator  / types   @ contract 1
```

示例数据契约可沿用现有 Demo：A 接收文本、输出对象或数组；B 接收 JSON、等待选择并输出任意 JSON 节点；C 接收 JSON、输出 TypeScript 字符串。契约不相容时应明确阻止或要求作者声明映射，宿主不能悄悄猜测字段转换；首版无需通用映射表达式引擎。

包 ID 不是信任证明。宿主必须保存用户审阅的来源与身份绑定；两个来源声称同一 ID 时阻止静默覆盖，要求用户选择来源。更新继续核对来源，不能让一个同名包接管既有依赖。旧包的来源 key、配置和数据按原规则保留，不自动改名迁移。

## 宿主调度、权限与生命周期

1. **运行前解析整条链**：查询已安装包的公开入口，校验版本、输入输出契约、执行模式、启用状态和授权，生成固定执行计划。缺失或不兼容时在首步前停止，不能先执行部分有副作用的步骤。
2. **按目标工具身份执行**：每一步使用目标包资源根目录、自己的动作配置、密码和存储；工作流包不继承或聚合依赖工具的权限。工具也不能读取前一步包的私有存储或配置。
3. **仅交接声明数据**：输入、输出通过宿主内存传递；不借剪贴板或共享临时目录偷渡数据。JSON 是数据，不能作为 Shell 或 JavaScript 源码执行。大文件传递如有真实需求，应另行设计有范围与有效期的宿主句柄，不能把任意路径视作授权。
4. **明确组合授权**：展示每个工具的发布来源、入口、副作用和数据流向，用户启用工作流时授权这条组合。工具的独立搜索开关控制可发现性，组合授权单独控制外包调用；关闭搜索不等于撤销组合授权。撤销任一步授权立即终止相关运行。
5. **串行推进真实入口**：脚本完成后校验输出；交互工具显示自身页面、等待一次提交。可复用现有 `workflow.context/complete` 的页面体验，但宿主需将会话绑定到运行 ID、步骤 ID、目标包身份及锁定版本；工具不能指定下一目标。
6. **取消与变更**：保留当前「重载恢复当前上游输入」「返回／关闭取消」「过期提交无效」语义。依赖包更新、重载、卸载或权限收回时，先取消并等待涉及该包的流程和任务退出，再替换文件；不能在一次运行中混用新旧版本。
7. **失败与重试**：报告失败包、入口、步骤及可操作原因，默认停止，不自动跳步；重试从头开始并提示可能重复已完成的副作用。不得宣称有事务回滚或崩溃后恢复。运行记录不默认持久化完整输入、输出或密码。

这里规划的是宿主 Bridge、资源、配置与数据的隔离。当前脚本以用户权限运行，**没有操作系统沙盒**；不能把组合授权描述成对任意脚本的强隔离。如要提供此保证，应另做进程沙盒与文件授权设计。

## 版本与缺失依赖体验

- 引入明确的新清单版本或经协商确定的能力门槛，确保旧客户端拒绝跨包清单；不能在当前 schema 4 中写入会被静默忽略的规划字段。
- 缺包、入口未导出、契约不兼容、身份冲突、权限未授予分别列明目标与原因，并提供查看来源、安装／更新／重新授权入口。依赖安装必须走既有审阅流程，不自动下载执行代码。
- 同一包首版只保留一个已安装版本；若不同工作流要求冲突版本，明确阻止受影响流程，不偷偷选择「最新」。首次授权及依赖／契约／权限变化后重新展示组合差异。

## 实施顺序与验收门槛

| 阶段 | 最小改动边界 | 完成条件 |
| --- | --- | --- |
| 1. 冻结格式 | `PackManifest` 定义稳定身份、公开入口、版本、依赖及纯工作流包；保留旧清单解析 | 旧包仍可导入；跨包字段在旧客户端明确拒绝；重复身份和非法引用有测试 |
| 2. 安装与解析 | `PackManager` 保存来源绑定，建立入口索引，解析完整依赖链 | 缺包、版本冲突、未导出入口在执行前阻止；迁移不丢配置或数据 |
| 3. 宿主执行 | 扩展现有 launcher/workflow 调度，逐步切换目标包会话、配置和资源根 | 混合脚本/UI 使用目标包权限，输入输出校验、取消和旧提交防护通过 |
| 4. 审阅与撤销 | 包详情展示依赖与组合授权，更新/卸载关联所有受影响运行 | 权限变化重新审阅；依赖替换前任务已退出；无静默权限扩大 |
| 5. 四包验收 | 三个独立工具包，加一个独立工作流包；示例和中英文文档同步 | 下列真实验收全部通过后，才能标记支持跨包 |

格式、解析和调度相互依赖，先串行落地契约与解析，再实现执行及授权界面。当前文档任务不启动这些生产代码修改。

四包验收必须使用四个独立导入目录／仓库和不同工具发布者标识；工具包彼此没有依赖：

- A、B、C 各自单独使用成功；移除工作流包后仍可使用。
- 第四包只声明依赖和步骤，不含工具实现；A → B → C 真实开页，B 等待用户选择，上游输出直接交接，C 与单独运行同输入结果一致。
- 工作流作者修改顺序或替换兼容的 C，无需修改 A/B 源码；不兼容的契约明确失败。
- 缺失 B、错误版本、未公开入口、同 ID 不同来源、未授权能力均在首步前失败，不能产生半段副作用。
- 运行中取消、重载当前页、重复／旧页面提交、撤销权限，以及依赖更新／卸载均有宿主测试；不能继续调用过期资源。
- 用真实不同包的存储、配置和权限验证隔离，并说明脚本 OS 沙盒仍不在保证范围；不可用一个大包中的三个页面冒充跨开发者验收。

验证应先做聚焦解析与调度检查，再于代码审阅、范围冻结后完成一次四包宿主与真实交互验收。结果分别记录源码检查、自动测试和人工操作证据；当前同包测试不能替代这道门槛。
