# AnyWhere 独立快捷启动器产品规划

日期：2026-09-09

## 目标

将 AnyWhere 的核心体验从设置页中的扩展包管理，收敛为类似 uTools、ZTools、Raycast 和 Alfred 的全局快捷启动面板。用户通过快捷键呼出面板，搜索并直接执行已安装扩展包提供的工具、动作和工作流。

设置页继续负责扩展包导入、权限审阅、启用、配置、更新和卸载；快捷面板负责高频执行。

## 已确认的产品决策

- 主入口是可配置的全局快捷键，菜单栏图标作为备用入口。
- 首屏只搜索已启用扩展包提供的工具、动作和工作流。
- 采用 A 方案：单列搜索结果。空搜索显示最近使用，输入后显示搜索结果。
- 工具和工作流默认在面板内展开，返回时保留搜索词和选中位置。
- 带 UI 的工具保留“在独立窗口打开”入口。
- 视觉上复用现有 AnyWhere 设置页和启动器的字体、颜色、圆角、阴影、选中态及深浅色适配。
- 第一版不加入应用搜索、文件搜索、在线推荐、账户系统、跨 Pack 工作流、拖拽编排和云同步 UI。

## 界面结构

面板是单实例半透明悬浮窗口，沿用现有快捷启动器的浮动层级和窗口行为。

顶部是聚焦的搜索框，显示搜索提示和 Esc 快捷键。内容区只包含“最近使用”或“搜索结果”两个列表分组。每行显示图标、标题、描述、类型和选中状态，键盘上下键移动，回车执行，Esc 关闭或返回。

执行工具或工作流时，内容区替换为工具页面或工作流结果页面，顶部显示返回按钮。动作直接调用现有执行链路；带 UI 的插件可从同一处打开独立窗口。错误在面板内显示，并提供返回和重试。

## 模块边界

### PackCatalog

复用 `PackManager`，读取已启用 Pack 并生成统一条目。条目包含类型、标题、描述、图标、关键词、Pack 标识和执行引用。旧 Pack 继续按照已有 manifest 规则工作。

### LauncherPanel

负责窗口、快捷键、输入焦点、选中项、键盘导航和面板状态，不直接执行脚本。

### LauncherResultList

根据搜索词过滤和排序。排序优先级为精确标题、别名、描述或关键词匹配，然后按最近使用时间排序。

### ExecutionRouter

按条目类型调用现有运行时：动作使用 `ActionRunner`，工具使用 `PluginSession`，工作流使用 `WorkflowExecutor`。同一工具的已有会话优先复用；独立窗口拥有独立会话。

### PanelState

只维护 `search`、`tool` 和 `workflowResult` 三种状态，以及搜索词、选中位置和当前会话。返回时恢复搜索上下文。

## 数据流

```text
全局快捷键 / 菜单栏图标
  → LauncherPanel
  → PackCatalog
  → LauncherResultList
  → ExecutionRouter
  → ActionRunner / PluginSession / WorkflowExecutor
  → 面板内结果或独立窗口
```

扩展包启用、禁用、更新和卸载后，目录刷新并影响下一次搜索。卸载或更新前关闭相关会话并等待正在执行的任务结束，失败则在面板或管理页中显示错误。

## 安全与错误处理

继续使用现有扩展包导入审阅、能力声明、脚本和路径校验。面板不扩大插件权限。脚本失败、插件加载失败、工作流步骤失败、取消和超时统一转换为可读错误，停止当前执行并保留返回入口。

## 分阶段交付

1. **面板基础**：快捷键唤起、现有视觉样式、目录搜索、最近使用和键盘交互。
2. **执行接入**：动作、工具、工作流、面板内结果、独立窗口入口和错误重试。
3. **管理联动**：启停实时刷新、更新/卸载关闭会话、最近使用持久化。

## 验收标准

- 快捷键稳定打开面板并聚焦搜索框。
- 搜索结果只来自已启用扩展包。
- 动作、工具和工作流均可从结果执行。
- 工作流步骤按顺序运行，失败后停止后续步骤。
- 关闭后再次打开不残留旧会话，返回保留搜索上下文。
- 浅色和深色主题与现有界面一致。
- 现有 Finder 菜单和扩展包导入流程不受影响。
- Core 测试、App 构建和启动自测通过。
