# AnyWhere 插件搜索入口与自定义 UI 设计

日期：2026-09-07

状态：设计草案，等待用户审阅；尚未实施。用户已确认快捷键唤起搜索框、按关键词打开插件，以及在同一搜索窗口内展开插件 UI。本文其余细则为建议默认行为，审阅通过后再形成实施计划。

## 1. 产品目标与边界

AnyWhere 提供两个可以独立使用的入口：

- 右键菜单：对当前选中的文件或目录执行功能。
- 插件搜索：通过全局快捷键唤起，查找并使用已安装插件的功能，不要求先选中文件。

两个入口共用扩展包身份、配置、数据与运行能力。同一包可以提供纯右键动作、纯搜索功能，或者同时提供两者。插件自带 HTML/CSS/JavaScript 实现界面；宿主不通过 JSON 定义页面布局和事件流程。

本文只设计 macOS 第一版插件搜索与自定义 UI。不实现跨应用选中文本服务、全盘搜索、应用启动器、云同步、插件市场改造、常驻系统插件、独立插件窗口或内置 Node/Deno。预留后续扩展的模块边界，不预先实现这些能力。已有 CLI 插件继续可用。

## 2. 方案选择

| 方案 | 得到的能力 | 代价与判断 |
| --- | --- | --- |
| 网页窗口加少量回调 | 展示页面、调用现有动作 | 不足以明确会话、数据和任务生命周期 |
| WebView、宿主接口、可选后端任务 | 自定义 UI、共享插件数据、调用脚本或二进制 | 推荐，覆盖已讨论的功能并沿用现有技术栈 |
| 完整 JS 后端运行时与常驻服务 | Node 或 Deno 生态、长期后台运行 | 本轮不引入；后续按插件需求单独设计 |

采用第二种。Swift 继续负责主程序；WebView 运行浏览器 JavaScript；插件可携带 Go/Rust 二进制或脚本作为任务后端。不会向开发者承诺 Node API 或所有 npm 包兼容性。

## 3. 搜索与窗口交互

### 3.1 唤起与搜索

- 提供一个全局快捷键，建议默认 `Control+Option+Space`，可在通用设置修改或停用。注册失败时保留原绑定并提示冲突，不自动占用其他组合；首次注册失败则不设置有效绑定。
- 菜单栏新增“打开插件搜索”，作为没有快捷键或注册失败时的可用入口。
- 全应用只有一个插件搜索窗口。首次唤起时在鼠标所在屏幕的可用区域居中显示；窗口已可见时不重新定位。
- 搜索范围只包含已安装并启用搜索入口的插件功能。导入后入口默认禁用，由用户启用，延续现有导入原则。
- 空查询显示最近使用的功能，最多 10 项；没有历史时按名称展示可用功能。最近使用仅保存功能身份及时间，不保存输入文本。
- 搜索忽略大小写，先按功能标题或别名完全匹配，再按前缀、包含关系排序；同级按最近使用和稳定身份排序。第一版不自动推导拼音，开发者可声明拼音或英文别名。
- 查询以标题或别名加空白开头时，剩余原文作为参数传入。多项匹配时取最长前缀；仍有歧义时展示候选，不自动执行。普通模糊搜索只用于定位功能，参数为空，完整查询另作为上下文传入。
- 方向键选中、回车进入。输入法组合输入期间，回车先确认候选，不启动插件。

### 3.2 展开插件 UI

- 插件直接展开在搜索窗口内。宿主顶部保留插件与功能名称、“返回搜索”按钮及错误提示位置；页面内部布局由插件决定。
- 进入后，搜索输入不持续干预插件内容。插件需要搜索或输入时，自行在页面中实现。
- 插件可以声明初始内容高度，宿主按当前屏幕可用范围约束。窗口可由用户调整尺寸，页面应自适应。第一版不提供任意窗口创建接口。
- 从搜索返回再进入功能时建立新会话；同一插件的数据通过持久存储保留，而非依赖隐藏网页。
- 从 Finder 进入 UI 动作时，在同一个插件窗口显示并携带本次文件上下文。纯脚本动作仍直接执行。

### 3.3 明确的状态与退出规则

| 当前状态与操作 | 结果 |
| --- | --- |
| 隐藏时按快捷键 | 恢复当前插件会话；无会话则显示搜索 |
| 搜索或插件窗口已在前台时按快捷键 | 隐藏窗口，保持会话 |
| 窗口失去焦点 | 保持窗口，不自动丢弃输入或取消任务 |
| 搜索状态按 Escape | 隐藏窗口 |
| 插件状态按 Escape | 先由页面处理下拉框、弹层或输入法；未处理时返回搜索 |
| 点击宿主“返回搜索” | 结束当前会话、取消其任务，恢复原查询和选中项 |
| 点击窗口关闭按钮 | 隐藏窗口，保留会话，与关闭整个应用区分 |
| 退出 AnyWhere | 结束所有插件会话及其受管理的任务 |
| 当前会话存在时收到新的功能调用 | 显示宿主“打开新操作”与“保留当前操作”选择；确认切换才结束旧会话 |

以上切换选择只用于保护现有会话，不用于每次普通打开时要求授权。隐藏时任务可以继续；返回搜索、确认切换、停用或卸载插件后任务结束。第一版不提供无界面的常驻后台功能。

## 4. 插件清单与兼容

新增能力要求清单版本 4。版本 1–3 的解析、动作 UUID、执行方式和配置位置保持兼容。

沿用 `actions` 作为包内稳定功能列表，不再并建一个重复的 `features` 列表。建议新增以下字段：

| 字段 | 含义与默认行为 |
| --- | --- |
| `action.ui.entry` | 包内 HTML 相对路径；缺省表示没有 UI |
| `action.ui.height` | 建议内容高度；省略时由宿主给出默认高度 |
| `action.launcher.keywords` | 提供此对象即注册搜索入口；关键词数组可为空，标题始终可搜索 |
| `action.contextMenu` | 是否注册右键入口，默认 `true`，保持旧包行为 |
| `action.script` | 已有脚本入口；纯 UI 功能允许省略 |
| `action.capabilities` | UI 所需宿主能力，第一版允许 `task.run` 与 `clipboard.write` |
| `pack.uiApiVersion` | 存在 UI 时要求显式声明，第一版为 `1`，与清单版本分别管理 |

约束：

- 动作至少有一个用户入口，以及 `ui` 或 `script` 中的至少一个执行入口。
- 有 UI 时，进入动作只加载页面，不隐式启动脚本。页面可在收到进入事件后调用自身动作声明的脚本。
- 无 UI 时，按现有规则执行脚本。搜索进入时没有选中文件；输入作为结构化调用上下文传入，不能拼接成 Shell 命令。
- 文件匹配规则只决定右键入口是否出现。搜索入口由插件明确声明；开发者不得把没有文件的搜索调用当作已有选中项。
- 页面、脚本、图片及其他资源必须位于包内，资源校验同时处理规范化路径、符号链接和编码后的路径，不能只做字符串前缀判断。
- 搜索启停与右键启停分别保存；停用一个入口不改变另一个入口。卸载会移除两个入口。
- UI 资源纳入导入和更新审阅，不执行安装脚本、不隐式运行包管理器下载依赖。

## 5. UI SDK 与调用上下文

宿主注入 `window.anywhere`，由 SDK 封装异步请求、事件订阅和标准错误。API 名称在本文属于拟定契约，不是已发布功能。

| API | 第一版语义 |
| --- | --- |
| `onEnter(callback)` | 页面完成就绪握手后交付一次调用上下文；订阅者不会因页面加载时序丢失事件 |
| `config.get()` | 读取当前动作已声明的普通配置，不批量注入密码 |
| `storage.get/set/remove(key, value)` | 读写当前插件的 JSON 数据；由宿主提供身份与串行写入 |
| `tasks.run(input)` | 执行当前动作已声明的脚本；返回任务句柄，用于结果、输出事件和取消 |
| `clipboard.writeText(text)` | 写入指定文本，要求声明 `clipboard.write` |

第一版仍在 AnyWhere 原生配置表单管理密码。任务执行时由宿主加载所需密码并注入现有配置环境变量；不向页面提供通用的密码读取接口。自定义密钥编辑或读取能力留到确有场景时单独设计。

调用上下文包含：协议版本、调用 ID、动作 ID、入口来源（搜索或 Finder）、完整查询、参数文本、选中文件列表。搜索调用文件列表为空；Finder 调用查询和参数文本为空。上下文是本次调用的不可变快照，不读取后续变化的 Finder 选择。

通信约定：

- 每个请求包含请求 ID、方法和参数；宿主绑定真实插件身份、会话 ID 与运行版本，不信任页面自报的身份。
- 每个请求最终只成功或失败一次；事件以会话和任务编号关联。页面关闭、刷新或更换会话后，旧回复不得进入新页面。
- 错误使用稳定代码和用户可读消息，至少区分参数非法、能力未开放、会话已结束、任务失败、超时和取消。
- Bridge 消息限制为 1 MiB，持久 JSON 数据每插件限制为 5 MiB；超过限额明确报错，不静默截断或覆盖旧数据。大文件内容不通过这一接口整体传输。
- 所有不可信内容按数据处理，不拼入 JavaScript 源码或 Shell 命令。日志屏蔽密码；宿主不默认记录参数全文和选中文本。

## 6. 后端任务

第一版采用一次启动、一次任务、完成退出的后端方式，复用现有脚本包装 CLI 的模式。Go/Rust 程序可由包内脚本调用；用户不需要安装编译工具。

- 插件页面调用 `tasks.run(input)` 时，宿主启动该动作已声明的脚本。不得传入任意可执行文件路径或任意命令文本。
- 保留现有选中文件参数和 `ANYWHERE_CONFIG_<KEY>` 环境契约；UI 提交的 JSON 参数写入该任务独有的私有临时文件，以 `ANYWHERE_REQUEST_FILE` 指向它。
- stdout/stderr 以有序文本事件提供给页面，并在任务退出后返回退出码及有界输出摘要；按 UTF-8 增量解码，不把每个管道分块假定为完整字符。
- 输出在发给页面或写入执行记录前遮蔽已知密码；遮蔽处理必须覆盖跨输出分块的密码片段。输出总量上限 4 MiB，超过时结束任务并报告输出过大。
- 本轮不要求已有 CLI 实现 JSON-RPC，不提供常驻请求服务器。之后需要持续通信时，可新增可选后端协议，不改变 UI 入口。
- 每个 UI 会话同时运行一个任务，重复运行返回忙碌错误，页面可先取消再启动。UI 任务使用独立调度，不占用原有右键脚本的串行队列。
- 沿用动作超时设置。取消只作用于宿主创建并记录的任务进程组；先请求退出，超出 2 秒仍未结束时终止该进程组，然后清理任务临时文件。
- 超时、取消、崩溃与正常退出均必须完成任务状态回收。不会声称这一机制能够管理主动脱离进程组的恶意程序。
- 二进制需由开发者提供适合目标架构和系统版本的产物及依赖；导入保留执行权限，并在运行失败时显示明确的架构或加载错误信息。

## 7. 存储、身份与访问范围

### 7.1 存储划分

安装文件与运行数据分开。现有 `PackConfigurations/<动作 UUID>.json` 及本地加密密码存储不迁移。

- 新增 `PluginData/<宿主管理的插件身份>/`，保存插件级 JSON 数据。多个功能共享这一空间。
- `storage` 参数只有键和值，不能选择其他插件身份或任意磁盘路径；写入采用原子替换，并在同一宿主内串行化。
- 密码继续使用现有本地加密存储与动作命名空间，不在插件普通 JSON 中复制一份。
- WebView 使用非持久会话数据，不依赖 Cookie、localStorage 或 IndexedDB 长期保存。正式持久数据通过宿主 API 保存，关闭会话后网页会话数据一并释放。
- 数据目录权限为 `0700`，数据文件为 `0600`。缓存和任务临时文件不视为用户持久数据。

### 7.2 身份及数据保留

第一版保留现有由来源确定的 `packKey`，宿主使用该身份划分新数据空间，不引入未经验证的全局插件自报 ID。

- 同一来源更新保留身份、配置与插件数据。
- 本地源目录移动后从新路径重新导入，或者更换仓库来源，按新插件处理；不自动继承旧配置。身份迁移属于后续单独功能。
- 卸载默认保留配置和持久数据，提供明确的同时删除数据选项。删除必须同时覆盖该包动作配置、密码及插件数据，并保留其他插件的数据。
- 清除数据前结束该插件的会话和任务；报告清理失败，不在部分清理成功时声称已全部删除。

### 7.3 网页与后端的信任范围

- 只向宿主加载的包内主页面开放 Bridge；不向 iframe 或跳转后的外部页面开放。
- 包内静态资源通过宿主限定的资源加载路径提供。第一版页面禁止直接联网、远程脚本和 iframe；联网业务可由已审阅的后端任务承担。
- 外部链接由宿主校验后交给系统浏览器，不把插件窗口导航到远程页面。
- 原生端逐次检查方法、参数、插件状态、会话和能力声明。插件更新增加能力时需再次展示变化，不能静默沿用对旧版本的启用状态。
- 上述隔离约束网页及宿主 API。现有脚本和二进制仍具有当前用户权限，不是系统沙盒；不能宣称能力列表限制了后端全部文件或网络访问。

## 8. 更新、故障与开发体验

- 更新先完成新包校验；如果旧版本有打开的会话，待用户确认结束会话和任务后再应用更新，用户取消则保留当前版本。
- 更新过程不能让旧 HTML 继续调用已替换的新脚本。新版本从新会话开始，持久数据保留。
- 不支持的清单或 UI API 版本在导入阶段拒绝，并显示所需版本；不会把未知 UI 字段静默降级成脚本执行。
- 页面加载或渲染进程失败时，宿主仍显示返回搜索和重载入口。重载建立新会话并结束旧任务。
- 第一版提供开发模式、本地包重新加载、可查看的 JS 错误与任务日志、SDK 类型定义和中文完整示例。开发工具只在明确启用开发模式时开放。
- 文档从中文 README 进入时始终进入中文页面；正式发布的扩展包规范与示例同步维护中英文版本。本文属于未发布的中文设计草案。

## 9. 实现归属与验收

现有入口主要位于 `App/AnyWhereApp.swift`、`App/ActionDispatcher.swift` 和 `App/ActionRunner.swift`；清单、配置、包导入分别位于 `PackManifest`、`PackSettings` 和 `PackManager`。

新增模块按职责划分为搜索索引、窗口会话、UI Bridge、插件数据存储及可取消任务执行。Finder 扩展只接收必要的菜单信息并派发动作，不加载页面、不保存插件数据、不执行后端。

清单、导入映射和启动方式相互依赖，应先串行确定同一份契约，再接窗口和 Bridge；不得分别实现两套功能身份或配置读取规则。

验收使用一个自定义文本工具示例包：纯 JS 页面完成文本处理和数据保存，另提供一个可调用的包内测试脚本展示输出与取消。现有 Xlog 包验证兼容性，不使用真实私钥或用户日志作为自动化测试数据。

| 验收面 | 通过条件 |
| --- | --- |
| 快捷键与输入 | 注册冲突可恢复；唤起和隐藏符合规则；中文输入法确认不误启动 |
| 搜索 | 名称、别名、参数解析与排序稳定；未启用入口不出现；最近使用不保存参数 |
| 多入口 | 同包可分别启用搜索与右键；文件快照正确；纯 UI 包没有脚本也能导入 |
| 会话 | 返回、隐藏、再次调用、更新和卸载行为符合状态表；旧响应不污染新会话 |
| 任务 | 输出、超时、取消、跨块密码遮蔽和进程退出有定向验证；不阻塞旧脚本队列 |
| 数据 | 插件间 API 隔离；更新保留；删除涵盖配置、密码和持久数据；失败不损坏原文件 |
| 资源与接口 | 越界资源、子页面调用、外部页面及过量消息被拒绝；错误可读且不泄露密钥 |
| 兼容性 | 版本 1–3 包、匹配规则、配置保存及 Finder 纯脚本调用保持现有行为 |

先完成契约及核心逻辑的定向验证，再审查最终代码树，最后进行一次 macOS 原生窗口与 Finder 集成验证。设计文档检查不代表这些运行验收已经通过。
