# 本机 MCP 与插件命令接入计划

目标：AnyWhere 提供一个本机 stdio MCP 服务。插件声明命令及导出列表；宿主提供 `list` 和每个插件的工具。Todo 首先导出查询、新建、修改、完成，界面和提醒按钮共用串行命令入口，拒绝旧版本覆盖。

按依赖串行实施，不启动并行实现：

1. 新增 schema 5 命令/MCP 声明、受支持的 JSON Schema 校验、授权持久化与协议测试。
2. 宿主按插件串行运行后台命令；限制受管键旁路写入，提供界面变更通知和提醒恢复。
3. 本机 Socket、stdio 辅助程序、动态工具注册、插件授权设置及打包。
4. Todo 共用命令模块，迁移界面/提醒操作，保留 schema 1 备份与现有提醒策略。
5. 针对并发、冲突、授权撤销、协议、提醒失败做开发测试；review 后冻结两个仓库树，再做一次最终原生集成验证。

验证：Core Swift 测试、Todo Node 业务测试、真实 WebView 命令/并发与 MCP 协议测试、Xcode 构建/相关宿主测试。没有 IDE MCP 编译能力时使用工程原生 xcodebuild。所有测试采用临时插件数据及授权，不改用户待办或客户端配置。

边界：仅本机服务；不发布、不修改 Codex 配置。保留两个仓库原有未提交内容，不自动提交。插件内命令声明和 MCP 导出分离；关闭 MCP 不关闭本地界面和提醒。

测试约定：命令含“保存后继续同步提醒”的异步阶段，不能把存储已经变化或 `ready` 当作操作结束；界面应在 busy 变化时立即渲染禁用状态，测试等待操作按钮就绪。自定义失败通知夹具应移除原插件的 commands/mcp 声明，不能引用未提供的后台入口。原生激活测试等待目标表单可见，不使用固定 50ms 延迟。
